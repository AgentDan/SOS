# Админка

Экраны для владельца: состояние системы, здоровье данных, правка любого раздела, публикация, откат, журнал и ручки. Это отдельная страница, не часть клиентского приложения. Сервер её не импортирует. Данные ходят в `/api/admin`.

## Запуск

1. В `.env` сервера задать `ADMIN_TOKEN` и при необходимости `PORT` (по умолчанию 3000).
2. Запустить сервер: `npm run dev:server`.
3. Запустить админку: `npm run admin`.

Страница открывается на `http://localhost:5174`. Запросы `/api` уходят на порт `PORT`. Токен вводится на экране входа и хранится в `sessionStorage` этой вкладки. В адресной строке, на экране и в консоли его нет. Кнопка «Выйти» стирает токен. Закрытие вкладки тоже.

В верхней панели видно, сколько разделов ещё не опубликовано. Кнопка «Проверить и опубликовать» открывает «Версии и журнал». Между заголовком и этой кнопкой — поле «Найти товар, вопрос, потребность…». Ctrl K (на Mac — ⌘K) открывает поиск и повторным нажатием закрывает его. Ищутся товары, типы, потребности, вопросы, ответы, сценарии и экраны. Товар открывается в каталоге, потребность и тип — на своей вкладке, вопрос и ответ — в анкете, сценарий — на вкладке «Сценарии». Реплики диалога и правила AI в поиск не входят.

Интерфейс собран на React (JSX). Сборка: `npm run build:admin` (то же делает `npm run check`). Результат лежит в `admin/dist`.

## Экраны

Меню слева: **Главная** (`#/overview`), **Каталог** (`#/catalog`), **Анкета** (`#/questionnaire`), **Диалог** (`#/dialog/consultant`; режиссёр, продажа, команды и правила AI подсвечивают тот же пункт), **Эргономика** (`#/ergonomics`), **Карта связей**, **Версии и журнал**. Ниже группа «Пока по-старому»: **Разделы** (`#/sections`), **Ручки** (`#/knobs`), **Модели** (`#/models`). Старые адреса разделов (`#/sections/<имя>`) работают как раньше.

- **Главная** (`#/overview`). Цель проекта. Четыре цифры: товары (сколько без модели), вопросы (сколько ответов), потребности (сколько без вывода) и неопубликованные разделы. Ниже — что ещё не опубликовано, здоровье данных, дыры в данных (те же проблемы, что на карте связей), плитки разделов и последние правки журнала. С главной ничего не публикуется и не правится: «Открыть» ведёт в раздел, «Проверить и опубликовать» и «Показать разницу» — в журнал.
- **Каталог.** Три вкладки: товары (таблица и карточка с формой, 3D-моделью и связями), типы и потребности. Публикация по-прежнему на экране «Версии и журнал». Режим JSON остался по адресу `#/sections/catalog`.
- **Анкета.** Три вкладки: вопросы (список по фазам, редактор вопроса и фишки вывода у ответа), сценарии и фазы. Клик по фишке или по клетке таблицы «Ответ → потребность» меняет уверенность по кругу: высокая, средняя, низкая, пусто. Порядок вопросов в фазе задаёт `priority`: чем больше число, тем раньше вопрос. Режим JSON остался по адресу `#/sections/questionnaire`.
- **Диалог.** Пять вкладок: консультант, режиссёр, продажа, команды сцены и правила AI (`#/dialog/<раздел>`). Ручки раздела стоят в этой же форме и сохраняются вместе с ней. Режим JSON по-прежнему открывается по адресу `#/sections/<имя>`.
- **Эргономика** (`#/ergonomics`). Форма роста, манекена, формул стола и допусков. Справа живой расчёт для выбранного роста и схема человека за столом. Режим JSON остался по адресу `#/sections/ergonomics`.
- **Разделы.** Тот же список. Внутри раздела — текст черновика, сохранение, публикация с полем «Что изменено», сброс несохранённого текста и история с откатом. Откат возвращает и черновик.
- **Ручки.** Значения по слоям. «Применить» пишет в черновик раздела. Клиент видит новое значение только после публикации этого раздела. Экран остаётся для ручек слоя «продукт»: цена товара и максимум типа на сцене.
- **Модели.** Загрузка GLB для артикула и переключатели физики на клиенте. Размеры в каталоге отсюда не меняются.
- **Карта связей.** Сценарии, вопросы, ответы, потребности, типы и товары: опубликованное, черновик и разница. Клик показывает цепочку узла. Кнопка «Открыть в редакторе» открывает узел в его редакторе.
- **Версии и журнал.** Слева изменения к публикации: проверка черновика, разница по полям и публикация сразу нескольких разделов с одним описанием. Справа журнал: последние 50, 100 или 200 записей, фильтры и откат. Откат возвращает и опубликованное, и черновик.

Каркас лежит в `admin/ui/`: рама страницы, меню с верхней панелью, окно поиска, карточка, кнопка, капсула, переключатель вкладок и поле с подписью. Цвета и шрифт заданы в `admin/app.css` токенами `paper`, `side`, `surface`, `line`, `ink`, `muted`, `accent`, `warn`, `bad` и мягкими подложками. Светлая и тёмная тема берутся из системной настройки. Экраны, которые уже были, пока рисуются своими цветами.

Несохранённый текст раздела спрашивает подтверждение при уходе со страницы и при переходе в другое место админки.

## Проверка

`npm test` включает `admin/**/*.test.js` (чистые функции, без браузера). `npm run check` дополнительно собирает клиент и админку через Vite.
